1. Overview

The CLAMS-Agent Benchmark is a cross-modal question-answering dataset built over archival broadcast video content from the American Archive of Public Broadcasting (AAPB). Questions are designed to require combining information from multiple modalities — speech transcripts, on-screen text, visual content, named entities, and speaker identification — to answer correctly.

The dataset is constructed by an automated pipeline that orchestrates specialized open-source tools through the CLAMS (Computational Linguistics Applications for Multimedia Services) platform, producing hierarchical structured video indexes. Questions are generated by an LLM using structured multi-modal evidence, then split into three evaluation tracks: multiple-choice, free-text, and visual-grounded.

Key Design Principles

  • Cross-modal requirement: Questions cannot be answered from any single modality alone. 95% of questions have grounding evidence from 2+ sources.
  • Grounded evaluation: Models must cite specific video segments and quote supporting evidence, not just produce an answer.
  • Dual-format: Inspired by MLVU and TempCompass, both multiple-choice (discriminative) and free-text (generative) tracks are included.
  • Adversarial filtering: MC distractors are tested with a "Deaf-Blind" protocol (CinePile) — an LLM attempts to answer without evidence, and questions where it succeeds are flagged.
  • Archival domain: Content spans 1960s–2000s broadcast television, presenting challenges from analog degradation, diverse production styles, and historical context.

Content Characteristics

  • Video quality: Varies from well-preserved digital transfers to degraded analog tape with noise, color distortion, and artifacts

3. Processing Pipeline

Each video is processed through a 7-stage pipeline of specialized open-source models, followed by post-processing for NER, entity resolution, relation extraction, and knowledge grounding.

1
Scene Detection (SWT) — app-swt-detection v8.3
CNN classifier identifies scene types: slate, chyron, credits, text overlays, negative (no text). Produces TimeFrame annotations with classification scores.
↓
2
Speech Recognition (Parakeet) — app-parakeet-wrapper v1.0 with parakeet-tdt-0.6b-v2
NVIDIA NeMo CTC/TDT model. Non-autoregressive architecture eliminates repetition artifacts common in autoregressive ASR (Whisper). Word-level timestamps.
↓
3
Shot Boundary Detection (TransNet) — app-transnet-wrapper with TransNetV2
Detects shot transitions to segment the video into coherent visual units. Used as primary temporal segmentation (preferred over SWT's coarse scene-level boundaries).
↓
4
On-Screen Text OCR (Qwen SWT) — app-qwen3vl-captioner with Qwen2.5-VL-3B-Instruct
Targets SWT-detected text scenes (slates, chyrons, credits). Extracts on-screen text via VLM prompting. Batch size 64.
↓
5
Visual Captioning (Qwen Shots) — app-qwen3vl-captioner with Qwen2.5-VL-3B-Instruct
Captions one frame every 5 seconds across all TransNet shots. Provides visual descriptions of b-roll, graphics, maps, people, and scenes. Batch size 64.
↓
6
View Merging — scripts/merge_mmif_views.py
Merges MMIF outputs from all stages into a single multi-view document with cross-view ID renumbering to avoid collisions.
↓
7
Speaker Diarization — NeMo ClusteringDiarizer (MarbleNet VAD + TitaNet embeddings)
Identifies speaker turns and clusters them. Speaker names resolved from chyron OCR text (preferred spelling authority).
↓
Post-Pipeline Processing
A
Named Entity Recognition — spaCy en_core_web_sm
Extracts PERSON, ORG, GPE, etc. from all text fields (ASR + OCR + captions). Filtered by groundability blocklist.
B
Entity Resolution — custom resolve_entity_variants()
Merges variant spellings (e.g., "Woodruff" + "Judy Woodruff" → "Judy Woodruff"). Prefers chyron/OCR spellings. Substring containment + QID matching. 2,011 variants merged across dataset.
C
Relation Extraction — spaCy dependency parsing
Extracts SVO (Subject-Verb-Object) triples with cross-segment overlap (handles sentences spanning segment boundaries).
D
Entity Grounding — Wikidata API + Wikipedia MediaWiki API
Links named entities to knowledge bases. Provides structured facts (occupations, positions, affiliations) and prose descriptions. 2s rate limiting between API calls.

Grounding Verification

Each question includes grounding metadata with verbatim excerpts from the source evidence:

{
  "grounding": {
    "speech_excerpt": "Dr. Krim discussed the latest research findings...",
    "visual_reference": "A chyron reads 'DR. MATHILDE KRIM, AIDS Medical Foundation'",
    "ocr_reference": "AIDS MEDICAL FOUNDATION",
    "reasoning": "The chyron identifies her organization while the speech provides her argument"
  },
  "source_segment_times": [{"start_ms": 130196, "end_ms": 158858}]
}

Grounding is verified against the index: 99% of questions have locatable evidence, 88% have verified speech excerpts, 65% have verified visual references.

Multiple Choice Distractor Pipeline

Inspired by CinePile, INQUIRER, and AutoConverter:

  1. Pre-filtering: Removes watermark/branding questions (91 filtered), applies per-video cap (max 10)
  2. LLM distractor generation: 4 error types — entity substitution, attribute modification, temporal confusion, partial/misleading
  3. Quality checks: Rejects >80% word overlap with correct answer; enforces ≥2 different error types per question
  4. Adversarial "Deaf-Blind" filter: An LLM attempts to answer without evidence. Questions answerable with ≥80% confidence are flagged.
    • 154 questions (30%) passed outright (blind LLM guessed wrong)
    • 367 questions (70%) kept as "hardened" (blind LLM guessed correctly but distractors retained)
  5. Format routing: Questions that fail distractor generation route to the free-text track instead

7. Evaluation Protocol

Grounded Evidence Requirement

Models must return structured JSON with both an answer and supporting evidence:

{
  "answer": "The AIDS Medical Foundation",
  "cited_segments": ["2:10-2:38"],
  "speech_evidence": "Dr. Krim discussed the latest research...",
  "visual_evidence": "Chyron reads: DR. MATHILDE KRIM, AIDS Medical Foundation",
  "ocr_evidence": null,
  "reasoning": "The chyron identifies her organization while she discusses research"
}

Three-Part Scoring

  1. Answer correctness: MC exact match or LLM-as-judge (5 dimensions, 0–5 each)
  2. Grounding verification: Cited evidence checked against index — do the quoted excerpts actually appear at the cited timestamps?
  3. Cross-modal citation: Did the model cite evidence from 2+ modalities?

8. Baseline Results

Index-Based QA Baselines

ModelBackendMC AccuracyGrounded MC Acc.Grounding VerifiedMulti-modal Cited
Qwen3:8bOllama79.1% (412/521)90.9%87%85%
Qwen3.5-9BvLLM59.9% (312/521)90.7%64%63%
Key finding: Grounded MC accuracy is nearly identical (~91%) for both models. The difference in overall accuracy is entirely due to retrieval — Qwen3.5-9B more often says "insufficient evidence" rather than guessing. When either model successfully retrieves and cites evidence, it answers correctly 91% of the time. This suggests the bottleneck is search/retrieval, not reasoning.

Ablation Studies

Removing modalities from the structured index to measure each component's contribution:

ConditionQwen3:8b MCQwen3.5-9B MCInterpretation
Full index79.1%59.9%Baseline — all modalities available
No ASR71.0% (-8.1)46.4% (-13.5)Speech contributes significantly to answering

Key finding: Removing any modality degrades performance, but the largest drop comes from reducing to ASR-only (-13.8 to -31.7 points). This proves that visual captions, OCR, entities, and relations all contribute meaningfully to answering cross-modal questions. The multi-modal structured index is not redundant with the speech transcript.

VLM Direct Comparison (Qwen3-VL-8B-Instruct)

Instead of using the structured index, feed raw video frames (+ optionally ASR) directly to a vision-language model:

ConditionRetrievalFramesASRMC Accuracy
Oracle 1 frameGround truth segment1No87.4%

Surprising finding: The VLM achieves 87% even with uniform sampling (no oracle retrieval). Qwen3-VL-8B is strong at reading on-screen text directly from frames. However, VLM answers are NOT grounded — the model cannot cite which segment or timestamp its evidence comes from. This motivates the combined approach below.

Combined Index + VLM (Microsoft DVD-inspired)

Structured index retrieval narrows the search space, then frame extraction + VLM provides visual verification:

ConditionMC AccuracyGrounded?
Index only (Qwen3:8b)79.1%Yes (87%)
VLM only (uniform 5f)87.2%No
Index + VLM combined82.3%Yes (100%)
The thesis argument: The combined approach provides both accuracy AND evidence provenance. While the VLM achieves higher raw accuracy, it cannot cite specific segments or quote evidence. The structured index enables grounded, auditable answers — essential for archival applications where catalogers need to verify claims against specific video moments. Training an agent to orchestrate these tools intelligently is the path to closing the gap with the VLM's raw accuracy while maintaining full grounding.

Related Research

This benchmark draws on methodology from:

  • MLVU (2024) — Dual-format (MC + generation) evaluation for long video
  • TempCompass (2024) — Same questions in multiple formats; temporal understanding
  • CinePile (2024) — Adversarial "Deaf-Blind" distractor filtering
  • INQUIRER — KG-based question generation with relation paths
  • Video-ChatGPT (2023) — 5-dimension LLM-as-judge scoring protocol
  • LongVILA-R1 (2025) — CoT-SFT + GRPO training for video reasoning
  • Video-R1 (2025) — Contrastive temporal reward (T-GRPO)
  • Agent-R1 (2025) — End-to-end RL for tool-use agents with process rewards
  • DramaQA — Cognitive difficulty hierarchy (L1–L4)
