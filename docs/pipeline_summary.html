2. Models Used

PySceneDetect — Shot Boundary Detection

Type: Content-based detector Backend: OpenCV GPU: Not required

Detects shot boundaries by analyzing pixel-level changes between consecutive frames. Uses the ContentDetector algorithm, which computes HSV color space differences and triggers a cut when the delta exceeds a configurable threshold. CPU-only and fast — processes a 1-hour video in ~2 minutes on Apple Silicon.

Output: TimeFrame annotations with start/end milliseconds and "shot" labels. Unlike SWT (Scenes With Text), PySceneDetect does not classify scene types — all segments receive a generic "shot" label. SWT provides semantic labels (bars, slate, chyron, credits, person) but requires GPU.

faster-whisper (small) — Automatic Speech Recognition

Architecture: Whisper (OpenAI) Backend: CTranslate2 Parameters: 244M Compute: int8 quantized, CPU

CTranslate2-optimized port of OpenAI's Whisper model, achieving 4× speedup over the original Python implementation with equivalent accuracy. The small model balances quality and speed for batch processing. Supports VAD (Voice Activity Detection) filtering to skip silence and reduce processing time.

Performance on this corpus: 30,470 words from ~4 hours of audio. Transcription speed varies: short clips process at 5–10× realtime; long broadcasts (40+ min) can drop below 1× realtime on CPU. The medium (769M params) or large-v3 (1.55B) models offer better accuracy for challenging audio (overlapping speech, archival noise).

spaCy en_core_web_sm — Named Entity Recognition

Architecture: CNN + HashEmbedCNN Parameters: 12M GPU: Not required Labels: 18 entity types

Statistical NER pipeline trained on OntoNotes 5.0. Extracts named entities from ASR transcripts with types including PERSON, ORG, GPE (geo-political entity), LOC, FAC (facility), EVENT, DATE, and more. The pipeline filters to "interesting" types (PERSON, ORG, GPE, LOC, FAC, EVENT), discarding numeric types like CARDINAL and ORDINAL.

Extracted 1,983 raw entity mentions (229 unique) from 30K words. Entity quality depends on ASR accuracy — whisper transcription errors propagate to NER (e.g., "Mundelein" tagged as PERSON when it's a city in Illinois). The larger en_core_web_trf (transformer-based, 438M params) offers better accuracy but is significantly slower.

nomic-embed-text — Semantic Embeddings

Architecture: BERT-based Dimensions: 768 Context: 8,192 tokens Served via: Ollama (localhost)

Open-source text embedding model used to generate dense vector representations of segment summaries for semantic search via ChromaDB. Each segment's fused summary (combining scene label, ASR transcript, OCR text, and entity descriptions) is embedded and stored for retrieval. Supports queries like "find segments about tourism in Hawaii" across the entire indexed corpus.

SWT Detection (ConvNeXt V2) — Scene Classification [GPU pipeline]

Architecture: ConvNeXt V2 (Large / Tiny) Task: Frame-level scene classification Labels: 10+ scene types GPU: Required

Two-stage CLAMS app: (1) CNN classifier predicts scene type per frame (TimePoint), (2) stitcher merges consecutive same-label frames into TimeFrame segments. Labels include: bars, slate, credits, chyron, person & chyron, other text, filmed text. Used for the cpb-aacip reference video (35 richly-labeled segments). Not available in current CPU-only batch.

Wikidata + Wikipedia — Entity Grounding [enrichment]

Source: Wikidata SPARQL API + Wikipedia REST API Fallback: DuckDuckGo web search

Three-layer lookup for each named entity: (1) Wikidata for structured facts (occupation, position held, date of birth), (2) Wikipedia for prose descriptions, (3) DuckDuckGo as fallback for entities not in knowledge bases. Results are stored in the index's grounded_entities field, enabling entity-linking QA questions.

qwen2.5:7b — Agent LLM [interactive mode]

Architecture: Qwen2.5 (Alibaba) Parameters: 7B Served via: Ollama Role: Tool-use reasoning

The LangGraph agent's reasoning backbone. In interactive mode (LangGraph Studio or TUI), the LLM decides which CLAMS tools to run, in what order, and with what parameters. Operates in an iterative loop: observe MMIF state → decide next tool → execute → observe result → repeat until done (max 10 iterations). Not used in the batch pipeline, which follows a fixed sequence.

Question Categories Explained

Scene Classification

720 questions • What scene type at timestamp? How many X scenes? First/last scene?

Tests visual understanding of scene boundaries and types. With SWT labels: bars, slate, chyron, credits. With PySceneDetect: shot boundaries.

requires_video MC supported

Text Extraction

765 questions • What is said at time X? Does video have dialogue? Summarize discussion.

Tests ASR transcript retrieval and comprehension. Includes both lookup (specific time range) and summarization tasks.

requires_audio asr

Named Entity

72 questions • What people/orgs/places are mentioned? Is X mentioned?

Tests entity extraction from spoken content. Includes positive/negative existence, type-filtered aggregation, and per-segment queries.

requires_audio MC supported

Entity Linking

58 questions • What is [entity]? Which entities are linked to knowledge bases?

Tests ability to connect mentioned entities to external knowledge (Wikidata/Wikipedia). Requires both entity recognition and world knowledge.

grounding wikidata

Cross-Annotation

616 questions • Who speaks during chyron? What follows the slate? Longest segment?

Multi-layer reasoning: joins scene labels with entities, transcripts with visual context. Includes temporal ordering and duration questions.

requires_video requires_audio

Temporal Reasoning

Embedded in cross_annotation • Before/after ordering, duration, sequence.

Tests understanding of temporal structure: scene ordering, person appearance order, segment duration comparison.

temporal MC supported

Our Unique Contributions

First Archival Broadcast Benchmark

No existing QA benchmark targets historical TV, news broadcasts, or public media archives. Despite massive collections (AAPB: 68K+ hours, Internet Archive TV News: 380K+ hours), no structured QA evaluation exists for this domain.

Multi-Modal Cross-Annotation

Questions that require jointly reasoning over scene type + ASR transcript + OCR text + named entities. "Who speaks during the chyron?" needs visual scene classification, speech recognition, and entity extraction simultaneously.

Structured Index Grounding

All answers are grounded in a machine-readable structured index with precise timestamps, confidence scores, and entity links. This enables automated evaluation without human judgment for most question types.

On-Screen Text Focus

Current video LLMs score below 47% on video OCR tasks (VidText, 2025). Our pipeline's pre-extracted OCR from slates, chyrons, and credits provides ground truth for evaluating text-in-video understanding.

Known Gaps (vs. State of the Art)

No Adversarial Filtering

CinePile 2.0 uses a "deaf-blind LLM" to identify questions answerable without video. We tag modality requirements but don't empirically test them. Planned: Run text-only LLM baseline, rewrite biased questions.

Template-Only Generation

Our questions follow fixed templates ("What scene at X?"). LLM-generated questions (CinePile, MLVU) are more diverse and natural. Planned: LLM-augmented generation from structured context.

No Multi-Hop Reasoning

Most questions are single-hop lookups. Multi-hop chains ("What org employs the person who speaks during the first chyron after the slate?") are underrepresented. Planned: Chain-of-evidence question templates.

Scale

2.2K questions vs. CinePile's 305K. Sufficient for evaluation but small for training. Growing the corpus and adding LLM generation will increase scale.

8. Next Steps

1. LLM-Augmented QA Generation

Feed structured index context to an LLM to generate natural-language questions, multi-hop reasoning chains, and more diverse question types beyond templates.

2. Deaf-Blind Adversarial Filtering

Run all questions through a text-only LLM (no video/audio). Questions it can answer correctly are biased — rewrite or discard them. Inspired by CinePile 2.0.

3. GPU Pipeline (SWT + OCR)

Re-process videos with SWT scene classification and docTR/SmolVLM2 OCR on Aristotle (GPU server). This will add rich scene labels and on-screen text extraction.

4. HITL Quality Review

Use the Gradio review app (already built) for human approval/rejection/editing of generated QA pairs. ELO tournament for comparing model answers.

5. Model Evaluation

Run the QA benchmark against video LLMs (Qwen-VL, LLaVA, Gemini) to establish baselines and identify where archival video understanding fails.

6. SFT Fine-Tuning

Generate chain-of-thought tool-use trajectories from the QA dataset for supervised fine-tuning of smaller models on archival video reasoning tasks.
