# V6 Grid-Driven Selective Tool Plan

## Goal

V6 should model how a human browses a long video: first perform a cheap visual/temporal survey, then selectively apply expensive tools to specific segments or frames. The model should not behave as if a fully precomputed semantic index is always available.

The hidden indexes can still be used as simulator fixtures for fast experimentation, but the visible tool contract should look like a new-video setting: the agent chooses what part of the video to inspect and which modality-specific tool to run there.

## Experimental Framing

We should separate three settings:

1. Warm-index archive QA: all ASR, OCR, captions, and other layers already exist. This is useful as an upper-bound-ish retrieval setting, but it is not the primary new-video orchestration task.
2. Cold-cache selective processing: the source index is hidden, the visible cache starts empty, and tools reveal only the segments the model chooses to process. This should be the primary V6 evaluation setting.
3. Oracle / diagnostic modes: use gold evidence or existing metadata to measure ceilings, validate question quality, and identify whether failures come from evidence retrieval, evidence selection, or answer synthesis.

The core V6 claim should be: an untrained or trained agent can efficiently build just enough evidence from raw long-form video to answer grounded questions, rather than pre-indexing everything.

## Tool Interface

The V6 interface should be small and range-oriented. Each expensive tool requires a time range or timestamp. Cost should scale with processed duration, number of shots, number of text scenes, returned context size, or a combination of those.

### `get_video_info()`

Returns basic metadata needed to plan browsing.

Arguments:
- None

Returns:
- Duration
- Title if available
- Collection/source if available
- Basic technical metadata if available

Cost:
- Free

### `get_video_grid(start_time, end_time, rows, cols, sampling)`

Returns a contact-sheet style overview of a time range. This is the cheap browsing primitive.

Arguments:
- `start_time`
- `end_time`
- `rows`
- `cols`
- `sampling`: `uniform`, `shot`, or `end_biased`

Returns:
- Grid cell IDs
- Cell time ranges
- Representative timestamps
- Contact sheet image when multimodal execution is available
- Text fallback with cell IDs and timestamps when image execution is not available
- Cell exploration status, such as fresh or already explored

The grid must not return semantic evidence that would require expensive tools. Specifically, it should not return ASR snippets, OCR snippets, VLM captions, named entities, topic labels, text-scene counts, speaker names, or precomputed summaries unless those were generated by prior visible tool calls.

Cost:
- Low, proportional to number of sampled frames and returned image size

### `get_frame(timestamp)`

Returns a single frame for targeted inspection. This can be optional in the first implementation if image plumbing slows the evaluation path.

Arguments:
- `timestamp`

Returns:
- Frame image with timestamp
- Optional frame ID

Cost:
- Low

### `get_transcript(start_time, end_time, model)`

Runs or reads ASR for the selected range.

Arguments:
- `start_time`
- `end_time`
- `model`: for example `parakeet` or `whisper`

Returns:
- Transcript segments in the selected range
- Segment timestamps
- ASR model used

Cost:
- Proportional to duration and model cost

### `get_text_on_screen(start_time, end_time, model)`

Runs text detection and OCR/VLM reading for the selected range. This is for chyrons, slates, title cards, credits, lower thirds, signs, and graphics.

Arguments:
- `start_time`
- `end_time`
- `model`

Returns:
- Detected text items
- Timestamps or time ranges
- Confidence-like diagnostics if available, treated as model/tool signals rather than calibrated probabilities

Cost:
- Proportional to text scenes found, frames inspected, and model cost

### `get_visual_description(start_time, end_time, model, task_mode)`

Runs visual captioning over shots or frames in the selected range.

Arguments:
- `start_time`
- `end_time`
- `model`
- `task_mode`: `general_scene`, `person_identity`, `action_event`, or similar

Returns:
- Shot/frame descriptions
- Timestamps
- Model used

Cost:
- Proportional to number of shots/frames and model cost

### `get_speakers(start_time, end_time)`

Runs or reads speaker diarization/identification for the selected range.

Arguments:
- `start_time`
- `end_time`

Returns:
- Speaker segments
- Speaker labels or names if available
- Timestamps

Cost:
- Proportional to duration

## Visible State Rules

The run cache should contain only artifacts created by visible tool calls during the current evaluation run.

Allowed hidden simulator behavior:
- Use `data/video_indexes/*.json` to return fast simulated outputs for selected ranges.
- Use existing shot boundaries to sample representative frames for `get_video_grid`.
- Use existing ASR/OCR/caption layers to emulate tools for only the selected range.

Disallowed visible behavior:
- Letting `search_transcript` query a transcript before ASR has been generated or made visible.
- Returning full-video semantic layers unless the agent explicitly paid for full-video processing.
- Exposing text-scene counts, topic labels, names, or captions through the grid.
- Treating the source index as the same thing as the run cache.

## VideoAtlas Adaptation

VideoAtlas is useful as a navigation pattern, not as a complete replacement for the CLAMS tool setting.

Elements to adapt:
- Coarse-to-fine grids for long-video navigation.
- Stable cell IDs rendered directly into the grid image.
- Timestamps rendered into each cell.
- Structured actions that reference cell IDs, not vague spatial language.
- A scratchpad of collected evidence items.
- Dead-zone masking or explored-cell status to discourage repeated inspection.
- Final answers based only on scratchpad evidence.

Elements not to copy directly:
- Uniform grid only. We should test shot-aware and end-biased grids.
- Pure visual/subtitle navigation. AAPB-style broadcast video needs ASR, OCR, visual captioning, and speaker tools.
- Zero-shot-only setup. We can evaluate zero-shot first, then train if there is a measurable failure mode.

## Grid Strategies

### Uniform Grid

Sample frames evenly across the selected time range. This is simple and matches the VideoAtlas baseline.

Use cases:
- General survey
- Topic transitions
- Locating credits near the end
- Finding visually distinct segments

### Shot-Aware Grid

Use shot boundaries to choose representative frames. This avoids redundant samples and aligns cells with coherent visual units.

Use cases:
- Visual QA
- Identifying title cards, studio shots, field reports, graphics, and interviews
- Segmenting long programs into visually coherent regions

### End-Biased Grid

Sample more densely near the end of the video.

Use cases:
- Credits
- Director/producer questions
- Closing title cards
- Sponsor/end-slate metadata

### Future: Task-Biased Grid

Task-biased sampling could use cheap signals such as frame difference, black frames, or layout heuristics. It should not use hidden semantic OCR/caption/entity data unless those signals are explicitly produced by visible tools.

## Agent Workflows

### General QA

1. Call `get_video_info()`.
2. Call `get_video_grid()` over the full video or a broad range.
3. Select promising cells based on visible visual evidence and question type.
4. Run modality-specific tools on narrow time ranges.
5. Add answer-bearing evidence to the scratchpad.
6. Produce an answer with citations to tool outputs and timestamps.

### Director / Credits / Production Metadata

1. Call `get_video_info()`.
2. Use an end-biased grid over the last portion of the video and optionally the first portion for slates.
3. Identify cells that visually look like slates, title cards, or credits.
4. Run `get_text_on_screen()` on those cells.
5. Deduplicate and reconcile names/titles.
6. Answer with citations to the slate or credit evidence.

This path should not require ASR unless the visible evidence is ambiguous and speech might clarify it.

### Moving Credits

1. Grid the last 5-10 minutes.
2. Identify cells with scrolling or dense credit text.
3. Run `get_text_on_screen()` on short overlapping ranges.
4. Merge OCR outputs across adjacent ranges.
5. Report extracted names/roles with timestamps and uncertainty notes.

### Guest / Interviewee Identification

1. Grid the full video or likely interview portions.
2. Identify interview setups, lower-third graphics, or studio guest shots.
3. Run `get_text_on_screen()` where chyrons appear.
4. Run `get_transcript()` or `get_speakers()` only if speech evidence is needed.
5. Reconcile OCR variants, such as `Bob Jones` vs `Bob Janes`, using nearby transcript, repeated chyrons, speaker labels, and edit distance as diagnostics.

## Scratchpad and Final Answer

The model should be encouraged to maintain a compact evidence scratchpad. The scratchpad is the bridge between tool orchestration and evidence selection.

For QA, evidence items should include:
- Evidence ID
- Tool name
- Timestamp or time range
- Short quoted or paraphrased observation
- Why it supports or does not support the answer

Example:

```json
{
  "evidence": [
    {
      "id": "E1",
      "tool": "get_text_on_screen",
      "time_range": "00:58:10-00:58:40",
      "observation": "Credit text lists Jane Smith as director.",
      "supports": "The director is Jane Smith."
    }
  ],
  "answer": "Jane Smith",
  "citations": ["E1"]
}
```

For cataloging tasks, evidence should include field-level support:

```json
{
  "field": "guests",
  "present": true,
  "values": [
    {
      "name": "Bob Jones",
      "evidence": ["E2", "E5"],
      "notes": "OCR variant 'Bob Janes' appears once; transcript context supports Bob Jones."
    }
  ]
}
```

Confidence values should be treated as model/tool-generated signals, not calibrated probabilities, unless we explicitly calibrate them against human labels.

## Evaluation Plan

Primary V6 evaluation should use single-agent mode. The same model should choose tools, read outputs, select evidence, and answer. The two-stage policy/answerer setup is useful as an ablation but should not be the main architecture.

Metrics:
- MC accuracy
- Free-text correctness
- Grounded accuracy
- Citation validity
- Evidence precision proxy, such as returned token count or irrelevant evidence volume
- Average tool cost
- Processed duration by modality
- Number of full-video calls
- Grid cells viewed
- Repeated-cell rate
- Cache artifacts created per question

Key comparisons:
- No-tools baseline
- Legacy warm-index single-agent baseline
- V6 cold-cache selective single-agent baseline
- V6 with uniform grid
- V6 with shot-aware grid
- V6 with end-biased grid for metadata questions
- Oracle evidence

## Cataloging Evaluation

Some questions should become cataloging-style tasks rather than ordinary QA:

1. Does this field exist in the video?
2. If so, what is the value and what evidence supports it?

Candidate canonical fields:
- Director
- Producer
- Host
- Guests
- Interviewees
- Speakers
- Program title
- Episode title
- Broadcast date
- Locations
- Organizations
- Sponsors/funders
- Chapter or story boundaries
- Credits

The model should be able to answer that a field is absent or not recoverable from visible evidence. This is different from simply producing a value.

## Cost Model

Costs should combine tool execution cost and context cost.

Execution examples:
- `get_video_info`: 0
- `get_video_grid`: low cost per sampled frame
- `get_transcript`: duration times ASR model cost
- `get_text_on_screen`: number of detected text scenes or inspected frames times model cost
- `get_visual_description`: number of shots/frames times VLM cost
- `get_speakers`: duration times diarization cost

Context examples:
- Penalize very large transcript dumps.
- Penalize broad visual ranges that return many captions.
- Penalize repeated calls over already-explored ranges.
- Charge full-video ASR as cheap but nonzero; it may be rational for speech-heavy questions but should not be mandatory for slate/credit/OCR questions.

This lets user preference change the optimal policy. If accuracy is weighted heavily, broad ASR plus targeted OCR may be worthwhile. If cost is weighted heavily, grid-first visual filtering may be preferred.

## Implementation Plan

### Phase 1: Eval-Only V6 Tools

Add `eval/v6_tools.py` with:
- `V6_TOOL_SCHEMAS`
- `execute_v6_tool()`
- Range validation
- Cost calculation
- Run-cache state
- Hidden source-index adapter for simulation

Update `eval/run_policy_answerer_eval.py`:
- Add `--tool-schema-mode v6`
- Use V6 schemas/executor when selected
- Keep single-agent mode as the primary V6 path
- Preserve legacy modes for comparison

### Phase 2: Grid Rendering

Implement `get_video_grid()` with:
- Text fallback first
- Contact sheet rendering when frames are available
- Burned-in cell IDs and timestamps
- Explored-cell status
- Optional dead-zone masking

Start with `uniform` and `shot` sampling. Add `end_biased` after the smoke test.

### Phase 3: Range-Limited Modal Tools

Map V6 tools to existing simulator outputs:
- `get_transcript` maps to range-limited ASR lookup or simulated ASR run.
- `get_text_on_screen` maps to text detection plus OCR/VLM reading inside the selected range.
- `get_visual_description` maps to caption layers inside the selected range.
- `get_speakers` maps to speaker layers if available.

If a layer is unavailable in the visible cache, the tool should create it for the requested range, not expose the full hidden layer.

### Phase 4: Scoring

Add scoring for:
- Correctness
- Grounding
- Citation validity
- Tool cost
- Returned context size
- Processed duration
- Full-video processing
- Repeated range/cell inspection

### Phase 5: Training

Do not start with SFT unless the base model fails the V6 interface in a specific way.

Preferred training sequence:
1. Evaluate untrained Qwen3.5-9B in V6 cold-cache selective mode.
2. Identify failure modes: bad grid selection, wrong modality, broad ranges, poor citation, poor evidence selection, answer synthesis errors.
3. Generate targeted demonstrations only for those failure modes.
4. Try rejection-sampled trajectories from the base model before hand-authored SFT.
5. Use GRPO from the base model for correctness, grounding, and cost once the reward is stable.

## Key Ablations

Run these before claiming training improvements:

1. No tools.
2. Legacy warm-index single-agent.
3. V6 cold-cache with no grid.
4. V6 cold-cache with uniform grid.
5. V6 cold-cache with shot-aware grid.
6. V6 cold-cache with end-biased grid on metadata/credits questions.
7. Transcript-only selective processing.
8. Visual-grid plus transcript.
9. Visual-grid plus OCR/text-on-screen.
10. Oracle evidence.

## Risks

Grid is too weak for speech localization:
- Allow full-video ASR, but charge execution and context cost. Also test chunked ASR summaries.

Grid accidentally becomes a semantic index:
- Keep `get_video_grid()` visually cheap. Do not return hidden ASR/OCR/caption/entity data.

Contact-sheet image execution is slow or unavailable:
- Start with text fallback and local/Aristotle smoke tests. Add multimodal contact sheets once the eval path is stable.

Too many tools confuse the model:
- Keep tools modality-based and range-based. Avoid exposing implementation details such as `run_asr` vs `read_asr` vs `search_transcript`.

Training hurts the base model:
- Treat Qwen3.5-9B zero-shot V6 as the baseline. Any adapter must beat it on grounded accuracy and cost, not just raw MC accuracy.
